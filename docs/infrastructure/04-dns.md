# 04. DNS

## Как устроено

DNS переводит имена в записи. `A` указывает IPv4, `AAAA` — IPv6, `CNAME` — другое имя, `MX` — почтовые серверы, `TXT` — проверочные и почтовые политики. Authoritative nameservers хранят зону; recursive resolver обходит DNS-иерархию и кеширует ответ на TTL (время жизни записи). Propagation — не мгновенная «рассылка», а истечение старых записей в кешах.

Для планового staging достаточно `staging.fetchnow.online A 77.239.107.143`. `AAAA` нельзя добавлять без работающей IPv6-маршрутизации. Изменение MX/TXT не нужно веб-сервису и может сломать почту или подтверждение домена.

## Проверки с рабочей машины и сервера

```bash
dig staging.fetchnow.online A +short
dig fetchnow.online NS +short
getent ahosts staging.fetchnow.online
nslookup staging.fetchnow.online
```

Первый вывод должен быть ровно `77.239.107.143`; второй показывает authoritative NS; `getent` отражает системный resolver; `nslookup` — дополнительная кросс-проверка. Сравните результаты локально и на сервере до Certbot.

`ping` проверяет ICMP, который может блокироваться, и не проверяет TCP/443, SNI, сертификат или HTTP. Для веб-сервиса используйте `curl -v https://staging.fetchnow.online/...` после настройки TLS.

## Ошибки и безопасный откат

- Старый IP: дождаться TTL и проверить authoritative ответ `dig @<NS> ...`.
- Несколько A: каждый адрес должен обслуживать сайт.
- `SERVFAIL`: проверить delegation/DNSSEC у провайдера.

**ROLLBACK:** перед изменением записать старые type/value/TTL; вернуть их через DNS-панель. Откат тоже ограничен кешами. Не снижать TTL в последний момент — это не очищает уже сохранённые ответы; снижайте заранее перед миграцией.
